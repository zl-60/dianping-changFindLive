# 宠伴生活 · 宠物服务与交流平台

**技术栈：** Spring Boot + MyBatis-Plus + Redis + Lua + RabbitMQ + Redisson + MySQL

**项目描述：** 基于 Spring Boot 开发的宠物服务与交流平台，支持宠物门店查询与附近门店发现、限量洗护优惠券领取、宠物洗护预约及到店核验，并提供宠友动态、点赞关注、Feed 流与用户签到功能。

**主要工作：**

- **登录与会话：** 设计双拦截器，第一层从 Redis 加载用户上下文并刷新 Token 有效期，第二层校验受保护接口登录状态；结合角色校验区分顾客与店主管理权限，请求结束清理 ThreadLocal。
- **优惠券秒杀：** 使用 Redis + Lua 原子校验活动时间、库存与一人一券限制，RabbitMQ 异步创建券订单；通过 MyBatis-Plus 条件更新扣减数据库库存，结合唯一约束和幂等消费防止超卖、重复发券，并补充待发送记录重试与失败库存补偿。
- **缓存设计：** 复用并完善通用 CacheClient，使用空值缓存防止缓存穿透，SET NX 互斥重建缓解热点缓存击穿；门店与服务规格更新提交后删除对应缓存。
- **社区与附近门店：** 使用 Redis ZSet 实现点赞用户排序、动态人气排行及 Feed 推送，使用时间戳与偏移量处理滚动分页；通过 Set 交集查询共同关注，GEO 检索附近宠物门店，Bitmap 统计当月签到与连续签到。
- **分布式锁与 ID：** 保留 SET NX + UUID 所有者标识 + Lua 释放的手写锁，并在订单消费等场景使用 Redisson 可重入锁及 watchdog 自动续期；复用“时间差高位 + Redis 自增序列低 32 位”的分布式 ID 生成器。

## 面试表述边界

- 说明项目基于黑马点评学习工程改造，重点讲宠物业务接入、预约优惠券事务、消息可靠性与页面闭环这些实际改动。
- “库存条件扣减”可以解释为基于条件更新的并发控制，没有使用版本号字段；不把它描述成实现了完整版本号乐观锁框架。
- ID 生成器参考时间戳与序列的组合思路，不是标准雪花算法，没有机器号字段。
- 当前只有主门店提供在线预约，多门店用于附近发现与探店关联。支付、退款、短信均为演示。
- 不填写未经压测获得的吞吐量、延迟或提升百分比。自动化并发正确性测试不等于性能压测。
