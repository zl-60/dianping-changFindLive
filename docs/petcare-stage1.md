# 宠伴洗护：第一阶段约定与验收

本阶段面向个人求职项目，提供单店到店服务的用户网页和店主工作台。促销、图文社区、AI 知识库属于后续阶段。

## 业务流程

**选服务规格 → 先选可用时间 → 填写宠物和联系人信息 → 提交并占位 → 模拟支付 → 店主确认 → 到店核验预约码 → 开始服务 → 完成 → 评价。**

价格和时长由用户先选的服务规格决定；填写信息后校验宠物种类和体重。没有独立宠物档案，一个订单对应一只宠物和一项服务。

| 决策 | 实现规则 |
| --- | --- |
| 时间精度 | 开始时间为整点，服务时长为整小时；多小时服务连续占位 |
| 预约范围 | 上海时区，包含今天的七天内，至少提前两小时 |
| 人员 | 只分配启用、有服务能力、排班覆盖完整时长且无占用的美容师 |
| 查看时间 | 不占位；进入信息页和真正提交时分别检查可用性 |
| 待支付 | 提交后保留十分钟；到期取消、释放资源 |
| 待确认 | 支付后等待三十分钟；到期取消、全额模拟退款 |
| 自行取消 | 未支付可取消；支付后的待确认/已确认订单须距开始至少两小时 |
| 临近取消 | 联系店主处理；服务开始前可由店主全额模拟退款 |
| 改约 | 取消后重新预约，不直接改变订单的时间、价格与服务 |
| 履约 | 店主核验预约码后记录到店，再记录开始和完成时间 |
| 迟到 | 不自动延长原预约时间；超过原时段不能开始，无法服务则店主退款 |
| 排班变化 | 阻止破坏有效订单的人员停用、能力删除、排班删除或缩短 |
| 换人 | 店主操作，校验新人员能力和空闲情况，事务内转移全部占位 |
| 评价 | 仅本人已完成订单，每单一次，1–5 星和文字 |
| 历史信息 | 保存服务名称、规格、价格、时长、宠物与联系人信息快照 |

每位美容师每天维护一段连续排班；美容师没有独立操作端。店主可以维护营业时间。

## 数据与并发

宠物入口为 `com.petcare.PetApplication`，原点评入口仍为 `com.hmdp.HmDianPingApplication`。前者单独扫描宠物模块，不启动原 Redis/RabbitMQ 组件；同一 Maven 工程保持单体架构。

新增表全部使用 `pet_` 前缀，不修改原 `tb_*` 表。默认演示使用文件型 H2，重启保留数据；支持通过环境变量连接 MySQL。这是为了在没有启动 Redis/RabbitMQ 时也能演示第一阶段。

单店所有预约资源写操作先锁定数据库中的一行 `pet_lock`，再处理订单与时段。`pet_slot` 的 `(staff_id, slot_start)` 主键为重复占位提供第二层约束；新增、释放、换人和状态变化处于同一事务。该做法针对单店容量，不以大规模平台吞吐为目标。

下单携带请求标识，同标识且同内容返回原订单，不同内容拒绝；支付重复请求不会重新计时或收款。后台每十五秒清理到期订单，相关业务操作也会先清理；到期后即使调度暂未运行也不能继续支付。

顾客与店主使用独立会话和服务端角色校验。顾客只能访问自己的订单；验证码五分钟过期、一次使用、最多五次错误尝试；店主密码使用 PBKDF2 验证并限制失败尝试。所有金额由服务器读取规格计算，忽略客户端报价。

## 演示与验收

1. 以匿名身份打开服务详情，选择规格，进入时间页：此时不出现宠物信息输入框。
2. 选择明天的一个可用时间，再填写宠物信息；提交时登录，表单内容保留。
3. 提交后查看十分钟支付倒计时；完成模拟支付，看到“待店主确认”。
4. 店主登录工作台确认；用户订单出现到店预约码。
5. 到预约当天，店主核验预约码；在原预约时段内开始、完成服务；顾客评价。
6. 新建另一笔订单，确认后取消：模拟退款完成，预约资源释放。
7. 测试脚本用可控时钟覆盖完整履约和十分钟/三十分钟超时，无需实际等待。

首次启动生成八个服务规格、三位美容师、七天初始排班，以及完成、取消、支付超时、接单超时的订单示例。查看示例订单使用手机号 `13800000001` 登录。初始排班只在首次创建服务数据时生成，店主修改后重启不会补回已删除排班；新增日期需在排班页设置。

## 接口索引

所有接口前缀为 `/api/pet`；返回 `{success, data}` 或 `{success:false, errorMsg}`。

| 接口 | 用途 |
| --- | --- |
| GET `/store`, `/services`, `/reviews` | 公开门店、规格、服务评价 |
| GET `/availability?specId=1&date=YYYY-MM-DD` | 可用整点时间与剩余人员数量 |
| POST `/auth/code`, `/auth/customer`, `/auth/owner` | 模拟验证码、顾客登录、店主登录 |
| GET `/auth/me`，POST `/auth/logout` | 当前身份、撤销会话 |
| GET/POST `/orders`，GET `/orders/{id}` | 本人订单列表、创建、详情 |
| POST `/orders/{id}/pay`, `/cancel`, `/review` | 模拟支付、本人取消、评价 |
| GET `/owner/orders`, `/owner/stats` | 店主订单与统计 |
| POST `/owner/orders/{id}/{action}` | confirm/reject/arrive/start/finish/cancel/noshow/reassign |
| GET/POST `/owner/services`，PUT `/owner/services/{id}` | 服务规格管理 |
| GET/POST `/owner/staff`，PUT `/owner/staff/{id}` | 美容师管理 |
| GET/POST/DELETE `/owner/shifts` | 排班管理 |
| PUT `/owner/store` | 门店设置 |

受保护接口携带 `Authorization: Bearer <token>`。顾客和店主各有独立 token；模拟支付不连接真实支付渠道，模拟验证码不连接短信渠道。
